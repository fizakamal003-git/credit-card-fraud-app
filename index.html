⚙️ How it works

1

You enter the 15 transaction details on the left, exactly matching the columns the pipeline was trained on.

2

The console assembles a single input row: merchant, category, amt, city, state, lat, long, city_pop, job, merch_lat, merch_long, transaction_hour, transaction_day, transaction_month, age.

3

In production, that row passes through the OneHotEncoder + StandardScaler preprocessing, then the Random Forest classifier. In this artifact, a labeled Demo Mode estimator stands in for that step.

4

The result panel displays the predicted class and an estimated confidence, styled the same way the real model's output would be.

🔌 Connecting your real model

This UI is structured so the real .pkl can be dropped in without a redesign. The runRealModel() stub in the code is where a backend call would go — replace its body with a fetch to your own API once one exists. Nothing here fabricates that connection.

  • fraud_detection_random_forest.pkl — your trained pipeline (preprocessing + Random Forest)
  • A small Python backend (e.g. Flask/FastAPI) that loads the .pkl with joblib.load() and exposes a POST /predict endpoint accepting the 15 fields as JSON
  • That endpoint returns {"prediction": 0|1, "fraud_probability": float} using model.predict() / model.predict_proba()
  • This HTML file's runRealModel() function updated to fetch() that endpoint instead of calling the Demo Mode estimator
